New techniques land every week. elevate watches the sources you choose: news sites, research papers, AI lab blogs, any feed you add. It checks whether a new thing is legit, and whether it would measurably improve one of your repos. When you approve, it sends a swarm of agents to open a draft PR.

Get started See how it decides
Gate 1

Is the new thing actually legit?

It checks source credibility, independent corroboration, community signal and public code, and gets a skeptical model review. Hype is kept, but hidden, along with the reasons it failed.

Gate 2

Will it make a real difference here?

It checks fit with this repo's stack, the risk and the effort, and requires a concrete measure of impact. The recommendation spells out exactly how the swarm will prove it.

You

Nothing ships without you

Only repos you opt in can be written to. Pull requests are drafts, and every swarm runs within a budget. elevate never merges and never pushes to a default branch.

How it works

From a headline to a draft PR, with evidence at every step.

Feeds are the same for everyone. Searches built from each watched repo's profile, its stack and domains, go out to HN, arXiv and GitHub, so what elevate finds is relevant to the code you actually have.

Swarm

Approve once. A team of agents does the work.

A planner reads the repo profile and fans the work out to implementers. A tester runs the before/after measure from Gate 2, and a skeptical reviewer on a second model checks the diff. Only then does a guarded publisher open the draft PR.

Built proof-first

The rules between a headline and your repo are proved, not just tested.

The gate decisions, the recommendation lifecycle and the write guard are specified and proved in Verus, following the PDD Kit method. One bug is planted per clause, and Verus must reject each one. The TypeScript the app runs is diff-tested against the proved code built to WASM, and a negative control shows that test can fail.
